# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект следует [семантическому версионированию](https://semver.org/lang/ru/).

Записи для версий 0.1.0–0.8.0 восстановлены по истории коммитов: файл
заведён при подготовке 0.8.1, а тегами отмечены не все прошлые релизы.

## [1.0.0] — 2026-09-04

Первый стабильный выпуск. Две большие темы: разбор перестал тихо врать,
а привязка к нормативке перестала быть утверждением на веру.

Формат правил, отчётов и baseline с этого момента стабилен — ломающие
изменения только со сменой мажорной версии.

### Ломающее изменение

Формат baseline поднят до версии 3: адрес находок D002 и D005 изменился.
Файлы от 0.8.x нужно перегенерировать через `--write-baseline`; старый
даёт понятную ошибку и код 2.

### Исправлено

Двенадцать дефектов, каждый из которых выдавал не ошибку, а
правдоподобный неверный отчёт.

- Строка вместо списка в `volumes`, `ports`, `cap_add` и `security_opt`
  обходилась по буквам: ложные срабатывания на символе `/` и пропуск
  смонтированного `docker.sock`.
- `pg_hba.conf` в форме «адрес отдельной маской» разбирался так, что
  методом становилась маска, а `trust` уезжал в options.
- U001 сравнивал `User` со строкой `root` буквально и пропускал `0`,
  `ROOT`, `root:root`.
- В юнитах systemd `#` и `;` резали значения в середине строки;
  продолжения строк не склеивались.
- Одно слово в строке `postgresql.conf` читалось как настройка: `sslx`
  превращалось в `ssl = x`.
- `docker-compose.yml` без секции `services` (формат v1) разбирался как
  пустой файл.
- Нечитаемый каталог не попадал ни в находки, ни в ошибки.
- Находка теперь важнее нечитаемого файла: прогон с critical-находкой и
  битым файлом возвращает 1, а не 3.
- Ошибка записи отчёта даёт код 2, а не трейсбек и код 1.
- Опечатка в `--select` даёт код 2, а не зелёный прогон.
- Подавляющий комментарий работает у директивы, у элемента списка и на
  заголовке сервиса.
- Падение одной проверки больше не уничтожает находки других правил.

### Нормативная привязка

Каждое из 41 правила ссылается на конкретные пункты, и все ссылки
проверяются тестами против перечней, выписанных из текстов документов.

- **Приказ ФСТЭК N 117** от 11.04.2025 (ГИС) — пункт 34 (мероприятия)
  или пункт 63 (базовые меры). Кодов вида ЗСВ.2 в нём нет.
- **Методический документ ФСТЭК** от 12.04.2026 — подмера раздела IV
  (`ЗКО.5`, `УПД.2`) и мероприятие раздела III (`КК`, `ПД`, `БР`).
- **Приказ ФСТЭК N 21** (ИСПДн) — мера в поле `pdn_measure`; приложение
  к приказу дало флаг `--uz` для базовых наборов по уровням.
- **ГОСТ Р 70860-2023** — предмет группы ЗКО задан через него, приказ
  ссылается на пункт 3.10.
- **ГОСТ Р 58833-2020** — severity правил об аутентификации: пароль это
  простая аутентификация (п. 6.9), она даёт низкий уровень доверия (7.2).
- **ГОСТ Р 56546** — класс уязвимости и тип недостатка в паспорте.
- **ГОСТ Р 56939-2024** — процессы разработки; самооценка проекта по ним
  в `docs/rbpo.md`.

### Добавлено

- `--format passport` — паспорта уязвимостей по ГОСТ Р 56545-2015,
  приложение А, со всеми обязательными элементами пунктов 5.1.2 и 5.1.3.
- `--uz {1,2,3,4}` — только базовый набор мер для уровня защищённости
  ПДн: от 27 правил на УЗ4 до 38 на УЗ1.
- C016 — сервисы не разделены по сетям.
- `docs/kzi.md` — структура показателя защищённости Кзи по Методике
  оценки ФСТЭК от 11.11.2025 и честная оценка вклада инструмента: 0,3125
  из 1,0 по четырём частным показателям из шестнадцати.
- `SECURITY.md`, `pip-audit` в CI, порог покрытия 90%.

### Сборка

`constraints.txt` с версиями инструментов, `mypy` в строгом режиме,
проверка кодов возврата на стендах, 283 теста при покрытии 95%.

## [0.8.1] — 2026-09-03

Релиз исправлений. Шесть дефектов разбора и фильтрации, каждый из которых
не поднимал ошибку, а выдавал отчёт, читавшийся как истина. Новых правил
нет, идентификаторы не менялись, формат baseline прежний — файлы baseline
из 0.8.0 продолжают работать.

### Исправлено

- Незакрытый heredoc больше не поглощает остаток Dockerfile. Шаблон
  срабатывал на любое `<<` перед идентификатором, поэтому
  `RUN echo "compare a << b"` и `grep x <<<"payload"` открывали heredoc с
  несуществующим ограничителем: `USER` и `HEALTHCHECK` исчезали из
  разбора, D001 и D006 срабатывали на образе, где они есть, а правила по
  инструкциям ниже молчали. Heredoc распознаётся только у RUN/COPY/ADD,
  `<<<` исключён, незакрытое тело откатывает позицию.
- Комментарий внутри переноса строки больше не обрывает инструкцию.
  Docker такую строку отбрасывает; парсер обрывал на ней `RUN`, и
  `curl | bash`, написанный после комментария, не сообщался вовсе.
- `--select` / `--ignore` останавливают разбор, а не только вывод. Файлы,
  все правила которых отключены, всё равно разбирались, и битый файл
  отключённого типа уводил CI в код возврата 3.
- Структурно неверный baseline сообщает об ошибке вместо трейсбека:
  список верхнего уровня, `findings` не списком или запись без поля
  дают `BaselineError` и код возврата 2.
- `DynamicUser=yes` больше не считается работой от root — systemd выдаёт
  сервису временный непривилегированный uid.
- Булевы директивы systemd читаются как в systemd (`1`/`yes`/`true`/`on`),
  а не только как `true`; `ProtectHome=tmpfs` засчитывается как защита.
- Сплошное подавление `# fstec-lint: ignore` больше не сужается
  перечнем правил, указанным на самой строке.
- C004 видит секрет в значении по умолчанию (`${DB_PASSWORD:-changeme}`);
  простая ссылка, пустой дефолт и соглашение `*_FILE` — по-прежнему не
  находки.
- `--list-rules` предупреждает о неподдерживаемом формате вместо тихого
  вывода в text.
- Неизвестная severity в файле правил называет допустимые значения
  вместо голого `KeyError`.

### Изменено

- GitHub Action ставит ревизию, с которой вызван (`github.action_ref`).
  Раньше `uses: ...@vX.Y.Z` закреплял только обёртку, а `pip install`
  внутри тянул HEAD; теперь пин тега пинит и версию инструмента.
- Сообщение U003 называет значения, которые проверка действительно
  принимает (`yes`/`full`/`strict`).

### Добавлено

- `docs/rules-subjects.md` — раздел «Что разбор не видит»: границы, за
  которыми «нарушений не найдено» означает лишь «в этом файле не
  найдено». `Include` в `sshd_config` и `include`/`include_dir` в
  `postgresql.conf` не раскрываются; `USER` внутри образа для C001 не
  виден.
- `tests/test_regressions.py` — по тесту на каждый случай, где инструмент
  был тихо неправ. Всего 219 тестов (было 183).

## [0.8.0] — 2026-09-03

### Добавлено

- Отключение правила тремя способами вместо одного: комментарий
  `# fstec-lint: ignore C001, C009` внутри проверяемого файла (действует
  на свою строку и следующую, понимает glob, без списка глушит строку
  целиком), флаги `--select` / `--ignore` для всего прогона, baseline.
  Число подавленных комментариями печатается в stderr.
- Флаг `--version`.
- Разбор условных блоков `Match` в `sshd_config`.

### Исправлено

- Разбор `sshd_config` останавливался на первом `Match`, поэтому
  `PermitRootLogin no` вверху файла и `PermitRootLogin yes` внутри
  `Match Address` сканировались как чистые. Внутри блока проверяется
  только явно заданное: унаследованное уже покрыто глобальной проверкой.
- Тело heredoc в Dockerfile больше не разбирается как отдельные
  инструкции — `apt-get` переставал быть «директивой APT-GET», а `USER`
  внутри heredoc — переключением пользователя.
- Пути в отчётах везде относительные: `text`/`json`/`html` печатали
  абсолютные, а SARIF и baseline — относительные, и отчёт из CI нельзя
  было сравнить с локальным.

## [0.7.0] — 2026-09-03

### Исправлено

- D001 и C001 проверяли только наличие `USER` / `user:`, поэтому
  `USER root` и `user: "0:0"` проходили как чистые. Теперь вычисляется
  эффективный пользователь и uid 0 ловится в любом написании.
- D004 срабатывало на `FROM builder` — ссылку на предыдущую стадию
  сборки, а не на внешний образ.
- `--platform=...` больше не принимается за имя образа; инструкции до
  первого `FROM` не теряются; распознаются диапазоны портов и формы
  `[::]:5432`; `$VAR` без скобок не считается секретом в открытом виде;
  `#` внутри кавычек в `postgresql.conf` не обрезает значение.
- Один битый файл больше не прерывает прогон: каждый файл разбирается
  отдельно, ошибки идут в stderr, добавлен код возврата 3 («часть файлов
  не удалось разобрать») отдельно от 1 («есть находки»).

### Добавлено

- Номер строки у каждой находки; для compose он берётся из узлов YAML.
- `partialFingerprints` в SARIF — сдвиг файла не создаёт новых алертов,
  а `startLine` перестал быть всегда единицей.
- Пропуск служебных каталогов (`.git`, `node_modules`, `vendor`, `.venv`)
  и флаг `--exclude GLOB`.

### Изменено

- `scan()` возвращает `ScanResult(findings, errors)` вместо списка.
- Формат baseline поднят до версии 2: старые файлы отвергаются с
  инструкцией, а не подавляют находки молча.

## [0.6.0] — 2026-09-02

### Добавлено

- Baseline: `--write-baseline` фиксирует текущий долг, `--baseline`
  подавляет его в CI, и сборка падает только на новых находках. Находка
  опознаётся по тройке «правило + файл + место», пути относительные,
  записи отсортированы для читаемых диффов.

## [0.5.0] — 2026-09-02

### Добавлено

- `--list-rules` — каталог правил и сводка покрытия групп мер ФСТЭК, в
  том числе явно показывающая, какие группы инструмент не закрывает.
- Тест целостности «YAML ↔ функции-проверки» в обе стороны: правило без
  функции и функция без правила молча ничего не делали.

## [0.4.0] — 2026-09-01

### Добавлено

- Шесть правил для Dockerfile (D001–D006): нет `USER` в финальной
  стадии, `ADD` по URL, секрет в `ARG`, незакреплённый `FROM`,
  `curl | sh`, отсутствие `HEALTHCHECK`. Всего 40 правил.
- Dockerfile в обоих стендах — демонстрация «до и после» покрывает и
  сборку, а не только конфигурацию времени выполнения.

## [0.3.0] — 2026-08-31

### Добавлено

- Шесть правил для `sshd_config` (S001–S006) и пять для юнитов systemd
  (U001–U005). Всего 34 правила.
- Формат вывода `sarif` для загрузки в GitHub Code Scanning.

## [0.2.0] — 2026-08-31

### Добавлено

- Семь правил: открытый Docker API, отсутствие лимитов ресурсов и
  healthcheck, включённый debug-режим, монтирование чувствительных путей
  хоста, отключённый аудит операторов, отсутствие `statement_timeout`.
  Всего 23 правила.
- Поле `orders` у каждого правила — к какому приказу оно относится.
- `ruff` и `mypy` в CI.

### Исправлено

- Проверки `pg_hba.conf` и `postgresql.conf` делили один реестр, хотя
  принимают данные разной формы; разнесены по двум.

## [0.1.0] — 2026-08-31

Первая версия: разбор `docker-compose.yml`, `postgresql.conf` и
`pg_hba.conf`, 16 правил с привязкой к мерам ФСТЭК, вывод в
`text`/`json`/`html`, коды возврата для CI, два стенда (уязвимый и
защищённый) и GitHub Action.
