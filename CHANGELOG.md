# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект следует [семантическому версионированию](https://semver.org/lang/ru/).

Записи для версий 0.1.0–0.8.0 восстановлены по истории коммитов: файл
заведён при подготовке 0.8.1, а тегами отмечены не все прошлые релизы.

## [1.0.0] — 2026-09-03

Первый стабильный выпуск. Нормативная привязка переустановлена по тексту
действующего приказа и по методическому документу к нему, обе проверяются
тестами. Формат правил, отчётов и baseline с этого момента считается
стабильным: ломающие изменения — только со сменой мажорной версии.

### Добавлено

- Поля `methodology` и `methodology_title` у каждого правила — группа мер
  методического документа ФСТЭК к приказу N 117: `КК` (контроль
  конфигураций), `ПД` (привилегированный доступ), `БР` (безопасная
  разработка), `УД` (удалённый доступ), `ЗУ` (конечные устройства),
  `НФ` (непрерывность функционирования).
- Группа выводится в текстовом отчёте строкой `группа:`, в JSON и в
  каталоге правил.
- `docs/measures-117.md`: таблица «группа → правила», раздел об
  архитектурных принципах методического документа и обратная таблица с
  колонкой группы.

### Решено сознательно

- Привязка к методическому документу ведётся на уровне группы, без
  номеров подмер: перечня подмер на руках нет, а номер, проставленный
  наугад, хуже отсутствующего.
- Правила P004, P005 и P007 (регистрация событий подключения,
  шифрование соединений, журналирование операторов) оставлены без
  группы: подходящих групп в имеющейся выписке нет. Отдельный тест
  фиксирует именно этот список, чтобы пустое поле нельзя было списать
  на забывчивость.

## [0.10.0] — 2026-09-03

Привязка мер переустановлена по тексту действующего приказа. До этой
версии коды мер в `rules/*.yaml` брались из приложения к приказу N 17,
утратившему силу 01.03.2026, и README честно предупреждал, что это
историческая справка, а не утверждение о соответствии. Теперь каждое
правило ссылается на конкретный подпункт приказа ФСТЭК России от
11.04.2025 N 117, и ссылка проверяется тестом.

### Изменено — нормативная привязка

- Поле `measure` каждого из 40 правил указывает на подпункт приказа
  N 117: пункт 63 (17 базовых мер защиты, подпункты а–с) либо пункт 34
  (22 мероприятия по защите информации, подпункты а–х). Кодов вида
  `ЗСВ.2` или `УПД.4` в приказе N 117 нет вообще — они были в
  приложении к N 17.
- Добавлено поле `legacy_measure`: код по N 17 сохранён как история
  миграции. Выводится в JSON-отчёте и каталоге правил, но не
  используется как утверждение о соответствии.
- `fstec_lint/measures.py` — перечни пунктов 34 и 63, выписанные
  дословно из приказа. Тесты `test_rules_integrity.py` не дают правилу
  сослаться на несуществующий подпункт, разойтись с формулировкой
  приказа или оставить в `measure` код утратившего силу N 17.
- Покрытие в `--list-rules` считается по пунктам приказа, а не по
  вырезанным из кода буквенным префиксам групп.
- `docs/measures-117.md` — матрица трассировки «мера → правила»,
  обратная таблица и явный перечень мер, которые инструмент не
  покрывает (9 из 17 базовых мер пункта 63).

### Исправлено — фактические ошибки в README

- «Состав мер расширен до 18 групп» — в приказе N 117 групп мер в
  прежнем смысле нет; есть 22 мероприятия (п. 34) и 17 базовых мер
  (п. 63).
- Группы `ЗПИ`, `ЗКУ`, `ЗИВ` как «новые обязательные группы мер»
  приказа N 117 — таких кодов в приказе нет. Защита программных
  интерфейсов существует, но как базовая мера п. 63 з), без кода.
- Правило C011 ссылалось на несуществующий код `ЗПИ.1`; теперь на
  п. 63 з) «Защита программных интерфейсов взаимодействия приложений».
- Ссылки на обзоры приказа убраны из раздела о правовом статусе:
  источник привязки — текст приказа.

### Добавлено — позиционирование

- README и `docs/measures-117.md` называют место инструмента в терминах
  приказа: поддержка мероприятий п. 34 б) (контроль конфигураций
  информационных систем) и п. 34 ф) (контроль уровня защищённости).
  Находки — вход для расчёта показателя защищённости Кзи (п. 31 а)), а
  не сам показатель.
- Зафиксировано, что правила про контейнер привязаны к п. 63 д)
  «Защита технологий контейнерных сред и их оркестрации» — мере,
  которой в приказе N 17 не было; отдельный тест держит эту привязку.

## [0.9.0] — 2026-09-03

Разбор кода целиком: двенадцать дефектов, каждый из которых выдавал не
ошибку, а правдоподобный неверный отчёт, плюс приведение сборки к
воспроизводимому виду. Новых правил нет, идентификаторы не менялись.

**Ломающее изменение:** формат baseline поднят до версии 3 — адрес
находок D002/D005 изменился (см. ниже). Файлы baseline от 0.8.x нужно
перегенерировать через `--write-baseline`; старый файл даёт понятную
ошибку и код 2, а не молчаливый пропуск половины принятого долга.

### Исправлено — тихие пропуски находок

- Строка вместо списка в `volumes`, `ports`, `cap_add`, `security_opt`
  больше не обходится посимвольно. `volumes: "/var/run/docker.sock:..."`
  давало ложные C015 (символ `/` как «смонтирован корень хоста») и при
  этом молча пропускало C008 и C003: ни одна буква не совпадала ни с
  `docker.sock`, ни с именем capability.
- `pg_hba.conf` в форме «адрес отдельной сетевой маской»
  (`host all all 192.168.0.0 255.255.0.0 trust`) разбирается верно.
  Раньше методом становилась маска, настоящий метод уезжал в options, и
  P001 молчал на записи, разрешающей вход без пароля.
- U001 распознаёт root во всех формах — `0`, `ROOT`, `root:root`, `0:0`.
  Правило сравнивало со строкой `root` буквально, хотя C001 и D001 про
  тот же предмет эти формы ловили. Предикат теперь общий на три правила.
- Юниты systemd: `#` и `;` считаются комментарием только в начале
  строки, как в самом systemd. Вырезание хвоста по ним рвало значения
  (`Environment="PATH=/a;/b"`, `ExecStart=/bin/sh -c 'a ; b'`).
  Продолжения строк (`\` в конце) склеиваются в одну директиву.
- Одно слово в строке `postgresql.conf` больше не выдумывает настройку:
  шаблон откатывался и читал `sslx` как `ssl = x`, то есть как значение
  реального параметра.
- Файл `docker-compose.yml` без единого ключа верхнего уровня
  современного compose (формат v1) сообщается как ошибка разбора. Раньше
  он разбирался как пустой и давал «нарушений не найдено».
- Нечитаемый каталог попадает в ошибки прогона. `os.walk` по умолчанию
  проглатывает ошибки листинга, и такой каталог давал ноль находок,
  ноль ошибок и код возврата 0.
- Значение с `$` в начале, не являющееся ссылкой на переменную
  (`$$ecret` — экранированный литерал, `$1234pass`), снова проверяется
  C004: отбрасывалось по одному первому символу.

### Исправлено — коды возврата и подавление

- Находка важнее нечитаемого файла: прогон с critical-находкой и одним
  битым файлом возвращает `1`, а не `3`. Порядок был обратный, и гейт,
  различающий эти коды, читал такой прогон как чистый.
- Ошибка записи отчёта или baseline (`--output` в несуществующий
  каталог, нет прав) даёт сообщение и код `2` вместо трейсбека и кода
  `1` — то есть вместо кода «найдены нарушения».
- Шаблон в `--select` / `--ignore`, не подошедший ни к одному правилу, —
  код `2`. Раньше о нём предупреждали в stderr, но прогон, не
  проверивший ни одного правила, завершался кодом 0 и выглядел как
  успешный аудит.
- Подавляющий комментарий работает и у нарушающей директивы, и на
  заголовке сервиса. Находки compose числились на строке объявления
  сервиса, поэтому `# fstec-lint: ignore C005` рядом с `ports` молча не
  срабатывал — вопреки примеру в документации.
- Падение одной проверки больше не уничтожает находки других правил по
  тому же файлу и не выдаётся за ошибку разбора: сообщение теперь
  называет правило (`сбой проверки C002: ...`).

### Изменено

- Адрес находок D002/D005 при усечении получает хвост-хеш полного текста
  команды. Две разные длинные команды с общим началом делили один адрес,
  а адрес входит в отпечаток — одна запись baseline глушила обе находки.
  Отсюда версия baseline 3.
- Поле `detail` у D002/D005 приводится к одной строке. Тело heredoc
  уезжало в него с переводами строк и рвало построчный текстовый отчёт.
- Ограничение размера разбираемого compose (8 МиБ).
  Раскрытие якорей PyYAML не грозит — `safe_load` переиспользует
  собранный объект якоря, а не копирует его.

### Сборка и проверки

- Версии инструментов разработки зафиксированы в `constraints.txt`.
- `mypy` в строгом режиме (`disallow_untyped_defs`,
  `disallow_incomplete_defs`, `strict_equality`); стабы PyYAML заданы
  секцией overrides, а не флагом `--ignore-missing-imports`, который
  всё равно не подавляет `import-untyped`.
- Порог покрытия 90% в CI (фактическое — 95%).
- Проверка кодов возврата на стендах: уязвимый обязан дать `1`.
- Action ставит инструмент из ревизии вызова, а при локальном вызове
  (`uses: ./`) — из самого чекаута, а не молча из `main`.

## [0.8.1] — 2026-09-03

Релиз исправлений. Шесть дефектов разбора и фильтрации, каждый из которых
не поднимал ошибку, а выдавал отчёт, читавшийся как истина. Новых правил
нет, идентификаторы не менялись, формат baseline прежний — файлы baseline
из 0.8.0 продолжают работать.

### Исправлено

- Незакрытый heredoc больше не поглощает остаток Dockerfile. Шаблон
  срабатывал на любое `<<` перед идентификатором, поэтому
  `RUN echo "compare a << b"` и `grep x <<<"payload"` открывали heredoc с
  несуществующим ограничителем: `USER` и `HEALTHCHECK` исчезали из
  разбора, D001 и D006 срабатывали на образе, где они есть, а правила по
  инструкциям ниже молчали. Heredoc распознаётся только у RUN/COPY/ADD,
  `<<<` исключён, незакрытое тело откатывает позицию.
- Комментарий внутри переноса строки больше не обрывает инструкцию.
  Docker такую строку отбрасывает; парсер обрывал на ней `RUN`, и
  `curl | bash`, написанный после комментария, не сообщался вовсе.
- `--select` / `--ignore` останавливают разбор, а не только вывод. Файлы,
  все правила которых отключены, всё равно разбирались, и битый файл
  отключённого типа уводил CI в код возврата 3.
- Структурно неверный baseline сообщает об ошибке вместо трейсбека:
  список верхнего уровня, `findings` не списком или запись без поля
  дают `BaselineError` и код возврата 2.
- `DynamicUser=yes` больше не считается работой от root — systemd выдаёт
  сервису временный непривилегированный uid.
- Булевы директивы systemd читаются как в systemd (`1`/`yes`/`true`/`on`),
  а не только как `true`; `ProtectHome=tmpfs` засчитывается как защита.
- Сплошное подавление `# fstec-lint: ignore` больше не сужается
  перечнем правил, указанным на самой строке.
- C004 видит секрет в значении по умолчанию (`${DB_PASSWORD:-changeme}`);
  простая ссылка, пустой дефолт и соглашение `*_FILE` — по-прежнему не
  находки.
- `--list-rules` предупреждает о неподдерживаемом формате вместо тихого
  вывода в text.
- Неизвестная severity в файле правил называет допустимые значения
  вместо голого `KeyError`.

### Изменено

- GitHub Action ставит ревизию, с которой вызван (`github.action_ref`).
  Раньше `uses: ...@vX.Y.Z` закреплял только обёртку, а `pip install`
  внутри тянул HEAD; теперь пин тега пинит и версию инструмента.
- Сообщение U003 называет значения, которые проверка действительно
  принимает (`yes`/`full`/`strict`).

### Добавлено

- `docs/rules-subjects.md` — раздел «Что разбор не видит»: границы, за
  которыми «нарушений не найдено» означает лишь «в этом файле не
  найдено». `Include` в `sshd_config` и `include`/`include_dir` в
  `postgresql.conf` не раскрываются; `USER` внутри образа для C001 не
  виден.
- `tests/test_regressions.py` — по тесту на каждый случай, где инструмент
  был тихо неправ. Всего 219 тестов (было 183).

## [0.8.0] — 2026-09-03

### Добавлено

- Отключение правила тремя способами вместо одного: комментарий
  `# fstec-lint: ignore C001, C009` внутри проверяемого файла (действует
  на свою строку и следующую, понимает glob, без списка глушит строку
  целиком), флаги `--select` / `--ignore` для всего прогона, baseline.
  Число подавленных комментариями печатается в stderr.
- Флаг `--version`.
- Разбор условных блоков `Match` в `sshd_config`.

### Исправлено

- Разбор `sshd_config` останавливался на первом `Match`, поэтому
  `PermitRootLogin no` вверху файла и `PermitRootLogin yes` внутри
  `Match Address` сканировались как чистые. Внутри блока проверяется
  только явно заданное: унаследованное уже покрыто глобальной проверкой.
- Тело heredoc в Dockerfile больше не разбирается как отдельные
  инструкции — `apt-get` переставал быть «директивой APT-GET», а `USER`
  внутри heredoc — переключением пользователя.
- Пути в отчётах везде относительные: `text`/`json`/`html` печатали
  абсолютные, а SARIF и baseline — относительные, и отчёт из CI нельзя
  было сравнить с локальным.

## [0.7.0] — 2026-09-03

### Исправлено

- D001 и C001 проверяли только наличие `USER` / `user:`, поэтому
  `USER root` и `user: "0:0"` проходили как чистые. Теперь вычисляется
  эффективный пользователь и uid 0 ловится в любом написании.
- D004 срабатывало на `FROM builder` — ссылку на предыдущую стадию
  сборки, а не на внешний образ.
- `--platform=...` больше не принимается за имя образа; инструкции до
  первого `FROM` не теряются; распознаются диапазоны портов и формы
  `[::]:5432`; `$VAR` без скобок не считается секретом в открытом виде;
  `#` внутри кавычек в `postgresql.conf` не обрезает значение.
- Один битый файл больше не прерывает прогон: каждый файл разбирается
  отдельно, ошибки идут в stderr, добавлен код возврата 3 («часть файлов
  не удалось разобрать») отдельно от 1 («есть находки»).

### Добавлено

- Номер строки у каждой находки; для compose он берётся из узлов YAML.
- `partialFingerprints` в SARIF — сдвиг файла не создаёт новых алертов,
  а `startLine` перестал быть всегда единицей.
- Пропуск служебных каталогов (`.git`, `node_modules`, `vendor`, `.venv`)
  и флаг `--exclude GLOB`.

### Изменено

- `scan()` возвращает `ScanResult(findings, errors)` вместо списка.
- Формат baseline поднят до версии 2: старые файлы отвергаются с
  инструкцией, а не подавляют находки молча.
