# История изменений

## [1.0.1] — предложенная версия

- Ограничена стоимость YAML alias-графа при загрузке правил до построения объектов.
- C004 проверяет литералы условных ветвей; D002/D003/D005 не выводят значения инструкций Dockerfile. Fingerprints D002/D005 изменились: проверьте и при необходимости пересоздайте baseline. Формат baseline остаётся v3.

- Исключены значения Compose defaults из C004 и опции HBA из locator P001/P002. Старые HBA-записи baseline v3 требуют явного пересоздания; порядок одинаковых структурных записей влияет на идентичность.
- Ограничены ресурсы YAML и baseline; внешние ссылки при рекурсивном обходе дают ошибку сканирования. Исправлены описание baseline, пример и справка `--exclude`.
- Ошибки загрузки правил теперь не отражают их значения и дают код CLI 2; циклы каталогов при обходе прерываются с ошибкой сканирования. Стоимость графа aliases ограничивается до последующих преобразований; см. `docs/security.md`.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект следует [семантическому версионированию](https://semver.org/lang/ru/).

Записи для версий 0.1.0–0.8.0 восстановлены по истории коммитов: файл
заведён при подготовке 0.8.1, а тегами отмечены не все прошлые релизы.

### Добавлено

- `--production-only` исключает определённые вложенные каталоги тестов и примеров по точному имени; не определяет назначение по содержимому.
- Рекурсивный обход пропускает служебный каталог `.agent-runs`.

- Привязка к Методике оценки уровня зрелости ФСТЭК России от 07.08.2026:
  модуль `fstec_lint/maturity.py` (21 направление, восемь видов
  требований с весами, шкала уровней, целевые уровни пункта 11) и разбор
  [`docs/maturity.md`](docs/maturity.md). Инструмент даёт материал в 9
  направлениях из 21 по видам требований «Инструменты» и «Контроль».
- `--list-rules` печатает направления методики зрелости, которые
  затрагивают правила; в JSON-каталоге — поля `maturity_directions` и
  `maturity_direction`.
- Тесты связывают три документа: каждое мероприятие пункта 34 приказа
  N 117 (кроме ГосСОПКА) и каждое мероприятие методического документа от
  12.04.2026 — ровно одно направление методики зрелости; таблица в
  `docs/maturity.md` не может разойтись с полем `activity` правил.

### Исправлено

- Диагностика ошибок сканирования не включает произвольный текст исключения и фрагменты конфигурации; для ошибок YAML сохраняется позиция, а для известного случая Compose v1 — фиксированное описание.
- Слишком глубокий JSON baseline обрабатывается как ошибка вызова с кодом 2.
- Диагностика некорректного baseline не отражает значения его содержимого.
- Composite Action передаёт значения через окружение и сохраняет границы аргументов, включая значения с ведущим дефисом.

### Известные ограничения

- Структура методики зрелости выписана по согласующимся изложениям, а не
  по тексту, опубликованному ФСТЭК России:
  `VERIFIED_AGAINST_PRIMARY_SOURCE = False` до построчной сверки.
  Пороги таблицы 3 и шкалы степеней выполнения не перенесены.

## [1.0.0] — 2026-09-04

Первый стабильный выпуск. Две большие темы: разбор перестал тихо врать,
а привязка к нормативке перестала быть утверждением на веру.

Формат правил, отчётов и baseline с этого момента стабилен — ломающие
изменения только со сменой мажорной версии.

### Ломающее изменение

Формат baseline поднят до версии 3: адрес находок D002 и D005 изменился.
Файлы от 0.8.x нужно перегенерировать через `--write-baseline`; старый
даёт понятную ошибку и код 2.

### Исправлено

Двенадцать дефектов, каждый из которых выдавал не ошибку, а
правдоподобный неверный отчёт.

- Строка вместо списка в `volumes`, `ports`, `cap_add` и `security_opt`
  обходилась по буквам: ложные срабатывания на символе `/` и пропуск
  смонтированного `docker.sock`.
- `pg_hba.conf` в форме «адрес отдельной маской» разбирался так, что
  методом становилась маска, а `trust` уезжал в options.
- U001 сравнивал `User` со строкой `root` буквально и пропускал `0`,
  `ROOT`, `root:root`.
- В юнитах systemd `#` и `;` резали значения в середине строки;
  продолжения строк не склеивались.
- Одно слово в строке `postgresql.conf` читалось как настройка: `sslx`
  превращалось в `ssl = x`.
- `docker-compose.yml` без секции `services` (формат v1) разбирался как
  пустой файл.
- Нечитаемый каталог не попадал ни в находки, ни в ошибки.
- Находка теперь важнее нечитаемого файла: прогон с critical-находкой и
  битым файлом возвращает 1, а не 3.
- Ошибка записи отчёта даёт код 2, а не трейсбек и код 1.
- Опечатка в `--select` даёт код 2, а не зелёный прогон.
- Подавляющий комментарий работает у директивы, у элемента списка и на
  заголовке сервиса.
- Падение одной проверки больше не уничтожает находки других правил.

### Нормативная привязка

Каждое из 41 правила ссылается на конкретные пункты, и все ссылки
проверяются тестами против перечней, выписанных из текстов документов.

- **Приказ ФСТЭК N 117** от 11.04.2025 (ГИС) — пункт 34 (мероприятия)
  или пункт 63 (базовые меры). Кодов вида ЗСВ.2 в нём нет.
- **Методический документ ФСТЭК** от 12.04.2026 — подмера раздела IV
  (`ЗКО.5`, `УПД.2`) и мероприятие раздела III (`КК`, `ПД`, `БР`).
- **Приказ ФСТЭК N 21** (ИСПДн) — мера в поле `pdn_measure`; приложение
  к приказу дало флаг `--uz` для базовых наборов по уровням.
- **ГОСТ Р 70860-2023** — предмет группы ЗКО задан через него, приказ
  ссылается на пункт 3.10.
- **ГОСТ Р 58833-2020** — severity правил об аутентификации: пароль это
  простая аутентификация (п. 6.9), она даёт низкий уровень доверия (7.2).
- **ГОСТ Р 56546** — класс уязвимости и тип недостатка в паспорте.
- **ГОСТ Р 56939-2024** — процессы разработки; самооценка проекта по ним
  в `docs/rbpo.md`.

### Добавлено

- `--format passport` — паспорта уязвимостей по ГОСТ Р 56545-2015,
  приложение А, со всеми обязательными элементами пунктов 5.1.2 и 5.1.3.
- `--uz {1,2,3,4}` — только базовый набор мер для уровня защищённости
  ПДн: от 27 правил на УЗ4 до 38 на УЗ1.
- C016 — сервисы не разделены по сетям.
- `docs/kzi.md` — структура показателя защищённости Кзи по Методике
  оценки ФСТЭК от 11.11.2025 и честная оценка вклада инструмента: 0,3125
  из 1,0 по четырём частным показателям из шестнадцати.
- `SECURITY.md`, `pip-audit` в CI, порог покрытия 90%.

### Сборка

`constraints.txt` с версиями инструментов, `mypy` в строгом режиме,
проверка кодов возврата на стендах, 283 теста при покрытии 95%.
