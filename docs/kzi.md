# Показатель защищённости Кзи и место инструмента в его оценке

Источник: **Методика оценки показателя состояния технической защиты
информации в информационных системах и обеспечения безопасности значимых
объектов критической информационной инфраструктуры Российской Федерации**,
утверждена ФСТЭК России 11 ноября 2025 г. Таблицы 1 и 2, приложение № 1.

Пункт 31 приказа ФСТЭК N 117 требует от оператора оценивать два
показателя: **Кзи** (текущее состояние защиты, пересчёт не реже раза в
шесть месяцев) и **Пзи** (уровень зрелости, не реже раза в два года).
Методика Кзи задаёт формулу, шкалу и подтверждающие материалы.

## Чем инструмент здесь является

Пункт 20 Методики перечисляет исходные данные для оценки. Подпункт «и»:

> результаты работы инструментальных средств оценки (анализа)
> защищённости информационных систем и (или) мониторинга информационной
> безопасности

Приложение № 1 конкретизирует это для отдельных показателей: для **k32**
требуется «отчёт, сформированный средством анализа защищённости», для
**k31** — «перечень интерфейсов (IP-адреса, доменные имена, физические
интерфейсы (порты)), доступных из сети „Интернет“».

Отчёт `fstec-lint` — такой подтверждающий материал. **Инструмент не
рассчитывает Кзи и не присваивает значения частным показателям**: это
делает орган (организация) по совокупности данных, включая
организационно-распорядительные документы, сведения об учётных записях и
настройки средств защиты, которых у статического анализа конфигураций нет.

## Формула и шкала

Пункт 34 Методики:

```
Кзи = (k11 + k12 + k13)·R1 + (k21 + … + k2i)·R2
    + (k31 + … + k3i)·R3 + (k41 + … + k4i)·R4
```

Нормированное значение (пункт 9): **Кзи = 1**. Пункт 35: повторное в
течение 12 месяцев невыполнение меры обнуляет весовой коэффициент **всей
группы**.

| Значение | Уровень состояния защищённости |
|---|---|
| Кзи = 1 | минимальный базовый («зелёный») |
| 0,75 < Кзи < 1 | низкий («оранжевый») |
| Кзи ≤ 0,75 | критический («красный») |

## Что это значит на практике

Из шестнадцати частных показателей инструмент даёт материал по
**десяти**; в них задействовано 27 правил из 53. Максимальный
вклад этих показателей в Кзи:

| Показатель | Вклад в Кзи |
|---|---|
| `k21` | 0.3 × 0.25 = **0.075** |
| `k22` | 0.3 × 0.25 = **0.075** |
| `k23` | 0.2 × 0.25 = **0.05** |
| `k24` | 0.2 × 0.25 = **0.05** |
| `k31` | 0.2 × 0.35 = **0.07** |
| `k32` | 0.25 × 0.35 = **0.0875** |
| `k33` | 0.15 × 0.35 = **0.0525** |
| `k34` | 0.15 × 0.35 = **0.0525** |
| `k41` | 0.4 × 0.3 = **0.12** |
| `k42` | 0.35 × 0.3 = **0.105** |
| **Итого** | **0.7375** из 1,0 |

Чистый прогон `fstec-lint` даёт исходные данные для показателей общим
весом около 74 % Кзи. Остальное — организационные документы (k11–k13),
централизованное управление антивирусной защитой (k35), очистка трафика
от DDoS у оператора связи (k36) и порядок реагирования на инциденты
(k43). По файлам конфигурации их не проверить.

Материал не равен выполнению показателя. Примеры:

- `k21`: инструмент проверяет, что парольная политика задана в
  `login.defs` и `pwquality.conf`. Есть ли учётные записи со старыми
  паролями, по конфигурации не видно.
- `k22`: проверяется только вход по SSH (`AuthenticationMethods`).
  Второй фактор в веб-консолях и VPN инструмент не видит.
- `k24`: проверяется, что учётная запись блокируется после истечения
  пароля (`INACTIVE`). Сверку списка учётных записей с кадровыми данными
  это не заменяет.
- `k33`: в расчёт идут критические уязвимости конфигурации. Уязвимости
  установленного ПО (CVE) выявляет сканер уязвимостей.
- `k34`: проверяется, что Postfix передаёт письма на внешний фильтр.
  Что это антивирус и что он проверяет вложения, по `main.cf` не видно.
- `k41`, `k42`: проверяется, что события пишутся и пересылаются
  (`rsyslog`, драйвер журналов контейнеров, `LogLevel` sshd). Работу
  SIEM и оповещение инструмент не проверяет.

Граница приведена, чтобы пустой отчёт не читали как выполненную оценку
показателя.
