# Подключаемые конфигурации PostgreSQL

## Параметры сервера: postgresql.conf

Поддерживаются `include 'file'`, `include_if_exists 'file'` и `include_dir 'directory'`.
Относительный путь отсчитывается от файла с директивой. Фрагмент читается на месте
директивы: последнее значение параметра побеждает. Находка ссылается на строку
победившего значения. В `include_dir` читаются отсортированные файлы `*.conf`,
кроме имён, начинающихся с точки. Имена заключаются в одинарные кавычки.

## Правила доступа: pg_hba.conf

В формате [PostgreSQL 16 и новее](https://www.postgresql.org/docs/16/auth-pg-hba-conf.html)
поддерживаются локальные `include`, `include_if_exists` и `include_dir`. Для имени
с пробелом или знаком `#` используйте двойные кавычки. Вложенные файлы подставляются
на место директивы. Каталог обрабатывается по имени файла в порядке локали C;
скрытые файлы, подкаталоги и файлы без расширения `.conf` пропускаются.

```text
# pg_hba.conf
include_dir "access rules"
include_if_exists "site-local.conf"
```

P001, P002 и P009 указывают на фактический файл и строку. Отсутствующий необязательный
файл пропускается. При цикле, выходе за границу, ссылке или неразобранном фрагменте
анализ помечается неполным; найденные в читаемых строках декларации не теряются.
Три проверки не моделируют, какая строка сработает для конкретного клиента, не
разворачивают списки имён через `@` и не проверяют продолжения строк HBA.

## Границы

Читаются только зависимости внутри корня проверки. Если входом был один файл,
корнем служит его родительский каталог. Правила обнаружения файлов не отменяют
явные зависимости уже выбранной конфигурации. Действуют пределы глубины,
числа файлов, объёма и обхода каталогов. Не сканируйте дерево, которое
одновременно меняет недоверенный субъект.
