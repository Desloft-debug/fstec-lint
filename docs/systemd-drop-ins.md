# Локальные переопределения systemd

Рядом с `app.service` линтер рассматривает `app.service.d` и общий
`service.d`. Для имён с дефисом учитываются префиксные каталоги, например
`web-.service.d` для `web-api.service`. Для явно переданного экземпляра
`worker@queue.service` учитываются также локальные настройки шаблона
`worker@.service.d`. Не создаются экземпляры, которых нет во входных файлах.

При одинаковом имени `*.conf` выбирается файл из более приоритетного
каталога. Файлы с разными именами затем применяются в общем
лексикографическом порядке. Для одиночных директив правил U001–U007
учитывается последнее значение. Находка ссылается на файл и строку,
из которых это значение получено.

Например, `app.service.d/40-home.conf` перекроет общий
`service.d/40-home.conf`, но `service.d/90-policy.conf` будет прочитан после
него. Если там указан `ProtectHome=no`, U005 укажет на строку в
`service.d/90-policy.conf`.

Это не состояние менеджера systemd. Каталоги ищутся рядом с выбранным
юнитом, без вычисления системных путей загрузки, псевдонимов, генераторов,
состояния работающего процесса или семантики списочных директив.
Ссылки, точки повторного разбора и недоступные либо неподдерживаемые
фрагменты не считаются полной проверкой.

[Справочник systemd.unit: расположение и порядок drop-in](https://www.freedesktop.org/software/systemd/man/latest/systemd.unit.html)
