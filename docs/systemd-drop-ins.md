# Локальные переопределения systemd

Для `app.service` линтер читает соседний каталог `app.service.d`. Файлы
`*.conf` применяются по имени. Для одиночных директив, проверяемых правилами
U001–U005, учитывается последнее значение; если оно задано во фрагменте,
отчёт ссылается на этот файл и строку.

Пример: если `app.service` задаёт `ProtectHome=tmpfs`, а
`app.service.d/90-local.conf` задаёт `ProtectHome=no`, U005 укажет на
строку в `90-local.conf`.

Это проверка файлов, а не состояния менеджера systemd. Не вычисляются общий
порядок поиска по системным путям, псевдонимы и свойства запущенного процесса.
Если рядом обнаружен общий, префиксный или шаблонный каталог, полная проверка
юнита не засчитывается. Недоступный или неподдерживаемый фрагмент также
делает результат неполным; базовый файл не выдаётся за окончательный.
Ссылки и точки повторного разбора в путях к фрагментам не поддерживаются.

[Справочник systemd.unit: расположение и порядок drop-in](https://www.freedesktop.org/software/systemd/man/latest/systemd.unit.html)
