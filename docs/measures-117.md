# Матрица трассировки: правило → пункт приказа ФСТЭК N 117

Составлена по тексту приказа ФСТЭК России от 11.04.2025 N 117
«Об утверждении Требований о защите информации, содержащейся в
государственных информационных системах…» (зарегистрирован Минюстом
России 16.06.2025, N 82619; действует с 01.03.2026).

Приказ N 117 признал утратившим силу приказ N 17 вместе с его
приложением, в котором лежала таблица кодов мер (ЗСВ.2, УПД.4 и
подобные). **В приказе N 117 таких кодов нет.** Вместо них Требования
задают:

* **пункт 34** — 22 мероприятия по защите информации (подпункты а–х);
* **пункт 63** — 17 базовых мер защиты информационных систем
  (подпункты а–с).

Детализация базовых мер до подмер выйдет в методических документах
ФСТЭК (пункт 31 Требований). До их публикации привязка ведётся на
уровне пунктов приказа — это то, что можно проверить по первоисточнику.

Перечни продублированы в коде (`fstec_lint/measures.py`), и тесты
`tests/test_rules_integrity.py` не дают правилу сослаться на
несуществующий подпункт или разойтись с формулировкой приказа.

## Что это за инструмент в терминах приказа N 117

`fstec-lint` — не средство защиты информации. Это инструмент поддержки
двух мероприятий оператора:

* **п. 34 б)** — контроль конфигураций информационных систем
  («исключать несанкционированное изменение состава программных…
  средств информационных систем, их настроек и конфигураций,
  установленных во внутренних стандартах по защите информации»);
* **п. 34 ф)** — проведение контроля уровня защищённости информации.

Результаты прогона — вход для расчёта показателя защищённости Кзи
(п. 31 а)), а не сам показатель: нормированные значения и методика
расчёта задаются методическими документами ФСТЭК.

## Группы мер методического документа

К приказу N 117 выпускается методический документ ФСТЭК, детализирующий
меры до подмер. На руках выписка по группам, относящимся к конфигурации,
архитектуре и развёртыванию, — то есть ровно к предмету статического
аудита. Привязка ведётся на уровне группы: номера подмер (КК.1, КК.2 и
подобные) в выписке отсутствуют, а проставленный наугад номер хуже
отсутствующего.

| Группа | Наименование | Правила |
|---|---|---|
| КК | Контроль конфигураций информационных систем | C009, C014, U003, U004 |
| ПД | Обеспечение защиты информации при предоставлении привилегированного доступа | C001, C002, C003, C008, C010, C015, D001, P001, P006, S001, S003, U001, U002, U005 |
| БР | Обеспечение разработки безопасного программного обеспечения | C004, C006, D002, D003, D004, D005 |
| УД | Обеспечение защиты информации при удалённом доступе | S002, S004, S005, S006 |
| ЗУ | Обеспечение защиты информации при использовании конечных устройств | C005, C007, C011, P002, P003 |
| НФ | Обеспечение непрерывности функционирования | C012, C013, D006, P008 |

Три правила группы не имеют: **P004**, **P005**, **P007** — регистрация
событий подключения, шифрование соединений и журналирование операторов.
В имеющейся выписке групп для регистрации событий и защиты каналов
передачи данных нет, и натягивать на них ближайшую по смыслу нельзя:
привязка перестанет быть проверяемой. По приказу N 117 они привязаны —
п. 63 в) и п. 63 с) соответственно.

### Архитектурные принципы

Методический документ отдельно формулирует принципы, которые ложатся на
проверку манифестов развёртывания целиком, а не на отдельное правило:

- выбор архитектурных решений на этапе проектирования — для уменьшения
  ширины и глубины поверхности компьютерных атак;
- принцип минимальных прав доступа к информационным ресурсам;
- минимизация интерфейсов, доступных субъектам доступа;
- сегментация и микросегментация по уровням значимости ресурсов;
- запрет на публикацию в сети «Интернет» сетевых сервисов, кроме
  публичных веб-приложений и необходимых для функционирования.

Последний принцип — прямое основание для C005 (порт СУБД на всех
интерфейсах), C011 (Docker API наружу), P002 и P003.

## Чего инструмент не покрывает

Из 17 базовых мер пункта 63 статическим анализом конфигураций
затрагиваются восемь: а), б), в), д), з), п), р), с). Не затрагиваются
и требуют других средств:

| Пункт | Мера | Почему не покрывается |
|---|---|---|
| п. 63 г) | Защита виртуализации и облачных вычислений | нужна конфигурация гипервизора и облачной платформы, а не файлы приложения |
| п. 63 е) | Защита сервисов электронной почты | вне области сканирования |
| п. 63 ж) | Защита веб-технологий | требуется анализ работающего приложения |
| п. 63 и) | Защита конечных устройств | данные о рабочих местах, не о конфигурации сервиса |
| п. 63 к) | Защита мобильных устройств | то же |
| п. 63 л) | Защита технологий интернета вещей | то же |
| п. 63 м) | Защита точек беспроводного доступа | конфигурация сетевого оборудования |
| п. 63 н) | Антивирусная защита | нужны данные о работающей системе |
| п. 63 о) | Обнаружение и предотвращение вторжений | то же |

Из мероприятий пункта 34 инструмент поддерживает б), г), з), к), м),
о) и, по назначению, ф). Остальные пятнадцать — организационные либо
требуют данных о работающей системе.

Пустой отчёт означает «в проверенных файлах нарушений не найдено», а не
«меры пункта 63 реализованы». Границы разбора выписаны в
[`rules-subjects.md`](rules-subjects.md), раздел «Что разбор не видит».
